# Architecture Decision Records

Use an ADR when a technical or product-architecture decision has meaningful alternatives or long-term consequences.

Naming:

~~~text
0001-short-decision-name.md
0002-another-decision.md
~~~

Template:

~~~markdown
# ADR NNNN — Title

> Status: Proposed | Accepted | Superseded
> Date: YYYY-MM-DD

## Context
## Decision
## Alternatives considered
## Consequences
## Follow-up
~~~

Likely early ADRs:

- UI framework choice;
- PPQ/time representation;
- audio clock strategy;
- project serialization format;
- text rendering stack;
- FFmpeg integration/distribution strategy.
